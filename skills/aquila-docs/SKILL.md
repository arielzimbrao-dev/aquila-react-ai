# aquila-docs — project documentation from the code

Precondition: `docs/ai/aquila.json` exists (otherwise run `/aquila-init`). Model and rules:
[`core/docs.md`](../../core/docs.md). **Everything from the real code**: every fact confirmed in the code;
whatever cannot be confirmed is marked "to confirm". Never delete documentation without showing the dev
what goes and where. By default do everything; with `$ARGUMENTS` (e.g. `context`, `c4`, `instructions`)
only that part.

## 0. Token warning

Follow [`core/tokens.md`](../../core/tokens.md) § High-consumption warning before reading the code.

## 1. Inventory what already exists (before writing)

The project almost always has written knowledge already: **incorporate it; do not duplicate it or
rewrite it from scratch**. List by metadata (path, size, first heading) and only then open what matters:

```bash
git ls-files '*.md' '*.mdx' '*.adoc' '*.rst' '*.mmd' '*.puml' '*.drawio' '*.dsl' \
  '*openapi*' '*swagger*' '*.stories.mdx' ':!:**/CHANGELOG*'
```

| Found (any folder)                                                                     | Destination                                |
| -------------------------------------------------------------------------------------- | ------------------------------------------ |
| ADRs / decisions (`adr/`, `decisions/`, `ADR-*`, "Decision", "Status: Accepted")       | `docs/adr/` — keep number, date, status    |
| Tracks, epics, master plans, roadmaps, backlogs                                        | `docs/tracks/<name>/` + registry           |
| Architecture, diagrams (C4, Mermaid, PlantUML, Structurizr, draw.io)                   | `docs/c4/` — basis for `aquila-c4`, not redone |
| API contract, routes/screens, design system, conventions, contribution guides, recipes | `docs/reference/`                          |
| Operations: deploy, rollback, incidents, feature flags, CDN, access                     | `docs/runbooks/`                           |
| AI instructions (`CLAUDE.md`, `AGENTS.md`, `.cursor/rules`, `.cursorrules`, `.windsurfrules`, `copilot-instructions.md`, `.github/instructions/`, skills) | facts → `CONTEXT.md`/per-folder instructions; domain → `reference/` |
| Module/package `README.md` files                                                       | stay; the `CONTEXT.md` map points to them  |

Incorporation rules:

- **One home per fact**: what is already written and matches the code stays where it will live; the
  `CONTEXT.md` and indexes **point**, they do not copy.
- **Doc ↔ code conflict** → the code wins; record the drift as "to confirm" and show it to the dev.
- Moving: propose to the dev (file → folder) **first**; then `git mv`, rewrite relative links and
  update generators/CI that write to those paths.
- Old AI routers: the aquila-react-ai managed block replaces the method; project-specific content migrates
  to `docs/ai/` and only then leaves the file.

After the docs inventory, the code inventory: folder structure, entry points (`main.tsx`, app shell,
routes/pages), providers (router, query client, store, theme, i18n), API clients and external SDKs,
client storage, design system, tests and config.

## 2. Generate (in this order; each file only with what belongs to the project)

1. **`docs/ai/CONTEXT.md`** (≤ 14.5 KB, template at `.aquila/templates/docs/ai/CONTEXT.md`):
   overview, stack, everyday commands, **"problem → where to look" map** (one line per area, real
   paths), layers and what each may import, **invariants** the code already enforces (section with
   "Invariants" in the title — it feeds Copilot PR review), large docs to read only by section, git/deploy.
2. **`docs/ai/golden.md`**: one real example per artifact type (the cleanest, not the largest), with 2–3
   lines on why ([`core/golden-files.md`](../../core/golden-files.md)).
3. **`.github/instructions/<area>.instructions.md`**: only for areas with their own rules; `applyTo`
   frontmatter with the real folders; ≤ 2.5 KB; project in a subfolder of the git repository (`doctor` says so):
   Copilot reads `.github/` only at the repository root, so write them there as
   `.github/instructions/<folder>-<area>.instructions.md` with `applyTo` prefixed by the folder (`backend/src/<area>/**`); **only the delta** vs `CONTEXT.md` and
   `.aquila/core/` — none of the generic method (test cases, style, checklist) aquila-react-ai
   already has.
4. **`docs/c4/`**: follow [`aquila-c4`](../aquila-c4/SKILL.md) (levels 1–3; level 4 only generated by
   script), starting from the diagrams found in the inventory.
5. **`docs/adr/`, `docs/tracks/`, `docs/reference/`, `docs/runbooks/`**: indexes (`README.md`) with what
   exists and what was incorporated; recipes ("new page / form / field") only if the project has
   repeated change patterns.
6. **`docs/README.md`**: index of the six folders, one line per document.

## 3. Validate and close

1. `npx aquila-react-ai sync` (the `copilot-instructions.md` block reads the invariants from CONTEXT)
   and `npx aquila-react-ai check` (links, budgets, instruction coverage) until green.
2. Show the dev: files created/changed/moved (with their origin) and what to validate ("to confirm"
   facts, doc ↔ code conflicts, golden files). During `/aquila-init`, return to that skill's final
   validation without asking for another command. In maintenance, `/aquila-audit` is optional for a
   broader assessment.
